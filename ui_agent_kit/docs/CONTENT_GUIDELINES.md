# CONTENT_GUIDELINES.md — Interface Copy

This file owns UI language and microcopy, not layout or styling.

## Voice
Concise, specific, calm, respectful, task-oriented.

Avoid marketing language in operational screens, vague labels, blame-oriented errors, and unnecessary jargon.

## Buttons
Use specific actions: `Save changes`, `Create class`, `Delete file`, `Send invitation`.
Avoid `Continue`, `OK`, or `Submit` when a clearer action exists.

## Headings
Name the content/task, not the container.

## Labels
Use established domain terminology; one term for one concept.

## Errors
Answer:
1. What happened?
2. What can the user do next?

Do not expose implementation details unless the audience needs them.

## Empty states
Explain why empty when useful and what the user can do next.

## Success
Use only when confirmation is useful; avoid redundant success banners.

## Confirmation dialogs
Title states the consequence; buttons use concrete actions, not `Yes / No`.

## Numbers, dates, units
Use locale-appropriate, consistent formatting.

## Placeholder/sample content
Never invent production claims or metrics. Mark representative prototype data clearly.
